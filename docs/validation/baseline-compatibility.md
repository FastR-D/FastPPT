# 基线偏移：源比例、字形大小与实际应用位置

2026-10-09。[可重放报告](baseline-libreoffice-7.3.7.2.json)包含 23 页实际原生导出：2 页与源字号模型吻合、21 页已知应用差异、0 页未预期差异。浏览器保留声明字号，以该字号的比例移动字形；LibreOffice 7.3.7.2 在这些非零偏移样例中把字形缩至约 58%，并将小数偏移截为整数百分比。两种行为不能宣称视觉等价。

```sh
pnpm --filter @fastppt/e2e exec tsx scripts/baseline-compatibility.ts /tmp/fastppt-baseline-compatibility
```

需要 LibreOffice 7.3.7.2、系统 Python UNO、Liberation Mono，以及可加载 PyMuPDF 的 `python3`。本轮使用 PyMuPDF 1.28.2；实际产物位于 `.fastppt/validation/baseline/`。报告绑定 PPTX、PDF、原始字形 JSON、应用初始配置和两个复现脚本的 SHA-256；没有修改导出的 XML，也没有用于替代验收的诊断副本。共享 LibreOffice 探针未改变，原有编号、制表、装饰和字距证据仍可重放。

打开实际文件前，独立检查 shape／paragraph 数量、逐字符原文、原生 `baseline`／`sz`、软换行、段落默认和段尾。原文通过 UNO 回读；PDF 记录每个真实字符的字体、字号、基线起点和边界框，禁止分析器虚构空格。位置容差 0.25pt，字号容差 0.05pt。预期和已知观察分开存放，回放测试必须重新判定，不能只信报告的 status。

| 样例 | 页数 | 观察 |
| --- | ---: | --- |
| -50／-25／-10／0／10／19／20／30／50／100% | 10 | 零偏移保留 20pt 字号；其余约 11.6pt。19% 与 20% 没有缩字阈值差别 |
| ±1.5／±0.5／±0.001% | 6 | 原生保留小数，应用仍缩字，但实际偏移按整数百分比截断；±0.5% 的实际基线与普通文字相同 |
| 60pt 行距、10pt／40pt 局部字号 | 3 | 偏移按声明字号计算，字形大小约为该字号的 58%；较大字号还改变首行位置 |
| 整行正偏移／负偏移 | 2 | 没有普通文字参照时也缩字；负值改变首行位置 |
| 软换行 | 1 | 原字符与换行保留，后续行偏移保留，行距 30pt |
| 空段 | 1 | 无虚构字形，默认值仍在原生段落中 |

探针使用 Liberation Mono 的 0.6em advance，以及未偏移样例的名义基线作为源字号模型。已知模型来自实现前的独立源属性探针与补充小数探针。例如声明 20pt／30% 时，基线移动约 6pt，但实际字形约 11.594pt；声明 20pt／0.5% 时，字形仍缩小而基线没有可见移动。负偏移与大字号对首行的影响有独立已知位置，不能只把整页平移后比较。这里验证原生属性及目标应用的观察值，浏览器像素等价仍为 `unverified`。

`baselinePercent` 表示声明字号的百分比，正值上移；缺省继承，零清除。源整数值按千分之一百分比解码，也接受 DrawingML 百分比字符串。契约范围为 -2147483.648 至 2147483.647，写入时按 0.001% 取整。比例不随画布缩放，字号正常缩放；原生字号不为模拟某个应用而改小。范围仅表示数据有效，不保证极端数值可在框内阅读。

九级字符默认、IR／MCP、统一固定文字、模板所有权和原生回读使用同一字段。页面作者可在源布局内用 `data-fastppt-baseline="30"` 覆盖，用 `0` 取消。投影仅移动实际文字叶节点，段落和 BR 保存独立默认，固定对象的外框不移动。普通逐脚本文字可合并成一个对象；直接叶节点捕获恢复名义坐标，避免原生再次偏移。制表行归属按未偏移位置判断，实际可见边界仍保留。

捕获校验元数据、实际字号和相对位移；无效值、错位 CSS、变换、额外水平位移或不匹配的 vertical-align 会阻断导出。相对字号的正常修改合法。旋转／非等比缩放的非零偏移仍不支持；任意 HTML sup/sub 或 CSS vertical-align 不会被推测成源比例。浏览器测试覆盖混排、链接、字距／装饰、空段、BR、Tab／折行、字符项目符号、固定文字、编辑与缩放。复杂文字框、RTL、动态字段和跨应用字形一致性未由这些测试验收。

参考 `pptx-renderer@2e8cd2222a889451bc872df50941f927cc79c7a2` 的源属性保留方式；其按偏移绝对值达到 20% 才将字体缩至 65% 的策略，与实际探针不符，因此未采用。PptxGenJS 的 legacy baseline 使用不同单位，FastPPT 明确采用新字段并在序列化后恢复源值；同时声明 legacy baseline／superscript／subscript 会报错，避免含糊优先级。

非零偏移正文、模板占位符和固定文字附加 `text-baseline-compatibility`，对象报告包含应用差异。该提示保留源语义，不表示兼容性已解决。实际产物渲染门禁及 PowerPoint／WPS／Keynote 的打开、编辑、保存与重开仍待后续验收。
