# 原生表格导出：首批验证记录

日期：2026-10-20。范围：N0 的表格运输/策略契约和 N1a 普通矩形表格。整体状态为 `partial`；结构回读通过不代表 PowerPoint/WPS/Keynote 的编辑操作或跨应用像素等价已验收。

## 已验证链路

- 标准 HTML 表格 → V2 整表捕获 → 原生 `a:tbl` → 最终文件回读；caption 独立保留，子树没有重复的文字/背景对象。
- 实际 Markdown 表格 → 独立 Slidev 预览 → runtime ready/工作台/Gateway 协商 V2 → 导出队列 → 实际 PPTX 下载 → 协议中的 table/结构验证报告保留。
- V1 兼容；旧能力声明按 V1 处理，双方无共同版本时明确诊断。消息协议仍为 V1，快照版本单独协商。
- 表头、非等宽列、空单元格和全空网格、中英文、inline 粗体/斜体及局部取消、链接、显式换行、纯色填充、折叠的实线边框、行边框、四边内距与垂直对齐；源编辑、字体加载及预览缩放后重新测量。
- 严格模式拒绝零图片的表格碎片，整表图片或原生内层表格也不能掩盖外层表格的结构损失；普通模式保留语义损失和原因。合并网格/复杂效果降级、非法矩形网格/原文不一致/超预算/越界阻断；超高表格不自动拆页或缩字。
- 最终产物检查实际 `graphicFrame/a:tbl`、唯一对象 ID、表格映射、行列及格数、原文、尺寸、内距、基础 rich-run 样式和边框宽度。篡改单元格原文会被拒绝。纯表格页文字纳入既有全局 QA。

## 实际应用观察

使用 LibreOffice 7.3.7.2 `30(Build:2)`，对 CLI 分发 writer 生成的原始文件直接执行 headless PDF 转换，然后用系统 Poppler 渲染到与浏览器相同的 980 × 552 尺寸。已查看浏览器截图和实际 PDF 回渲染：网格、列宽、行数、单元格内容、链接颜色、局部字体粗细和显式换行均保留，未见缺格或文字覆盖；字形和基线仍有细微差异，不声称像素等价。该操作只证明本次文件可被此版本 LibreOffice 打开并渲染。

未进行 PowerPoint、WPS、Keynote 的修改单元格、插删行列、合并拆分、保存和重开操作。对象报告中的 `verification.visual/application` 仍为 `unverified`，不由本次静态观察自动升级。

保留产物位于工作区 `.fastppt/validation/native-tables/2026-10-20/`：真实浏览器快照、浏览器 PNG、原生/编辑后/工作台 PPTX、分发 writer PPTX 与对象报告、LibreOffice PDF/PNG，以及 `hashes.json`。这些是本地验收证据，不是发布文件。
