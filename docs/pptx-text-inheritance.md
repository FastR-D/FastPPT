# PPTX 文字继承与源布局投影

分析器将原始属性与继承结果分开保存：`sourceTextStyles` 包含 presentation `defaultTextStyle` 和各 master 的 `txStyles`；`sourceObjects` 保留段落、默认 run、正文 run、软换行、段尾和 `fontRef` 的属性及 XML；`resolvedObjectText` 按 part / shape / paragraph / run 输出逐属性合并结果。

继承优先级从低到高：presentation 默认样式 → master 默认样式 → master title/body/other 样式 → master 占位符列表样式 → layout 占位符列表样式 → 当前形状列表样式 → 当前段落 `pPr/defRPr` → 当前 run `rPr`。形状的 `fontRef` 在同层列表样式之前应用。每层先应用 `defPPr`，再应用对应 `lvlNpPr`；九个列表级别独立求值。

页面占位符按 idx 匹配布局，再按类型匹配母版。省略 type 的页面占位符使用匹配布局的类型选择 title/body/other 样式。存在重复匹配时记录歧义，不任选一个。模板示例文字的 run 不作为其他页面的默认样式；`endParaRPr` 单独解析，不影响相邻正文 run。互斥的项目符号、颜色、字号和字体属性按组替换，例如 `buNone` 会取代继承的 `buChar`。

同一个属性节点中，互斥组出现多个成员或单项重复时，不采用最后一个，也不回退到父层。该项从解析后的 children/origins 中移除，issues 标出冲突类型、part、shape、作用域、级别或段落/run；原始 XML 和所有候选节点仍留在 sources/sourceObjects。随后合法的近层属性可以得到明确解析值，但源冲突诊断继续保留，生成候选仍须审查。此检查覆盖已经提取到 children 的项目符号／字体／大小／颜色、下划线属性、tabLst 和段间距等；不是完整的 OOXML schema 校验。外来命名空间的同名节点不参与标准属性组。

每个最终属性携带 `origins`，指出来源 part、shape、样式作用域、列表级别或段落/run 位置；`sources` 保留参与合并的 XML 片段。继承结果标为 `derived`，不修改 `extracted` 原始对象。

文本框 `bodyPr` 的属性通过 `resolvedGeometry[].placeholders[].appearance.textBody` 逐字段继承并保留 attributeOrigins。来源还保存完整的子属性树；互斥的 noAutofit/normAutofit/spAutoFit 选择最近一层明确设置，记录选择来源。重复选择或其他未支持子节点保持定位问题，不用父层替代有歧义的近层。布局 noAutofit 可覆盖母版 normAutofit，原始母版 XML 仍保留。

## 字体和颜色

字体按 Latin / East Asian / complex script 分别继承。明确的字体名直接保留；`+mj-*` / `+mn-*` 使用当前 part 通过关系图取得的 Theme/Override。主题空脚本字体只有在语言或 Unicode 脚本证据足够时才解析 supplemental font，例如 zh-CN → Hans、zh-TW → Hant、假名 → Jpan、阿拉伯字母 → Arab。无法区分地区的汉字、缺失映射或重复映射保留未解析原因，不替换成任意通用字体。

颜色使用当前 part 的 theme、override、clrMap 和源颜色变换求值。主题字体结果记录实际字体方案的来源 part，包含 override 来源。主题字体名称解析成功并不证明该字体已安装、已嵌入或目标应用使用了相同字形。

项目符号类型、字体、大小、颜色四组分别继承。`resolvedBulletFont` 解析 buFont 的主题字体引用；`resolvedBulletColor` 求值 buClr 的颜色角色与变换，并保存 sourcePart。buFontTx/buClrTx 保留“随正文”的语义，不提前固化成统一值；原始节点和四组的来源指针仍保留。不合法或不能表达的颜色、字体属性、图片标记与未实现的编号格式继续产生来源定位问题。

## 生成和导出的当前边界

源布局生成器消费 `resolvedObjectText`，将可表达的字体、字号、颜色、粗体、斜体及段落属性写入 `native-layouts.json` 和对应 Vue 命名槽位。九个级别共有的属性成为基础值，其余分别写入 `textStyle.levels`；不会用一级的显式字体或字号填补其他级别的未声明值。段落保留对齐、左右缩进、首行缩进、行距和段前段后间距，缺省、显式零值和 false 保持不同含义。

字符符号和常用自动编号现在投影为 `paragraph.bullet/bulletFont/bulletSize/bulletColor` 四组契约，buNone 可局部取消。原生 XML 按颜色、大小、字体、符号的 schema 顺序写入；点值随画布缩放，百分比保持比例。Vue 已测量左／中／右／两端对齐的 LTR 标记段落，包括非负缩进和超出悬挂区的长编号；首行占用与源缩进分别保存。前缀占满框宽、居中／右对齐段落中的 Tab、其他编号格式、图片标记、透明颜色及未表达的字体属性继续阻断／保持 partial。

不同脚本字体分别保存为 `textStyle.fontFamilies.latin/ea/cs`，对应分析证据的 `latin/eastAsian/complexScript`；只有三种字体均明确且相同时才合并为旧版 `fontFamily`。固定文字也使用解析后的 run，避免遗漏 presentation/master 的默认样式。示例段落的格式仍不替代模板默认值；当示例属性不能由对应级别的可复用契约表达时继续记录定位问题。

原生 `textStyle` 的未声明段落属性使用左对齐、零缩进、无项目符号、段前段后零间距、1.2 倍行距，以及常规装饰和基线，避免继承种子母版的居中与逐级缩进；显式 paragraph/levels 按字段覆盖这些值。`kern=0` 表示所有字号启用 kerning，对应浏览器 `font-kerning:normal`。源文本占位符生成独立 textBody 契约：保留四边内边距、垂直对齐、是否折行，并明确禁用自动缩放；缺省采用 DrawingML 左右 91440 EMU、上下 45720 EMU 和顶部对齐。不支持的自动适应、负内边距、竖排、旋转或其他 body 属性仍使候选保持 partial。页面显式 run/段落覆盖仍按绑定策略保留，级别身份不因选择布局继承而被抹除。

源 Vue 槽位按字素分段应用字体，不依赖 CSS fallback 顺序猜测脚本；字体已安装或存在对应字形仍需另行确认。默认捕获将没有额外视觉效果的生成字体包裹层合并成一个文本对象。对需要整体绑定的多段文字，可以在带段落契约的源槽位中使用 `div[data-fastppt-text-box]` 和一个独立锚点；快照保存 paragraphs、逐 run 样式与链接，再输出一个原生文本形状。保留空段和软换行，普通字重／斜体 false 明确写入，避免被布局覆盖。显式布局继承继续逐段移除已声明属性，保留各级身份。使用示例见 [原生布局绑定](native-layout-bindings.md)。

文本编辑后会重新投影 Vue 节点，静态 HTML 与其中的独立 SVG 子树分别处理。显式文本框只接受普通流中的段落和行内文字：有图片、额外效果、复杂几何、独立子锚点或未支持的排版时给出定位错误并阻断导出。自行渲染文字的组件仍需审查；无标记的富文本继续沿用原有逐对象捕获，不自动合并。

字符符号和自动编号必须在显式文本框中捕获。显示用的独立标记随首个可见 run 和画布变化更新；捕获验证内容、悬挂位置、字体、大小、颜色和可见性，再保存为段落属性，正文字符串不含标记。空段保留契约但不显示标记。`data-fastppt-no-bullet` 可取消单个段落／列表项的符号；若绑定选择布局文字继承，布局明确声明的标记组仍会覆盖该局部取消。文字编辑、级别变更、折行和软换行保留唯一形状身份。

固定文字的不同脚本字体及项目符号、占位符未实现的标记／制表位／RTL 格式、文字效果、动态域或无法表达的正文样式仍保留来源证据，并使候选保持 `partial`；不把它们降成统一字体后宣称完整。深层字体映射参与完整样式比较，仅字体不同的级别会生成独立覆盖；示例 run 仍须与对应级别匹配。未声明 `textStyle` 的手写原生布局仍可能继承种子默认值。占位符内边距已按画布横纵轴独立缩放，并由 textBody: page/layout 独立控制继承；复杂富文本、自动适应、固定文字框体和 Office 字体度量仍需后续实现／视觉验收。显式文本框可编辑不等于已经验收任意源 PPTX 富文本。

## 验证与参考

回归包括逐字段继承、显式 false 覆写、段尾/软换行隔离、列表级别和项目符号切换、脚本字体解析及歧义、原始证据不变，以及真实 PPTX → 分析 → 源主题 → 原生导出 → 分析回读。真实样例在母版定义脚本字体和字号，并让二级独立改变大小、字重、对齐、缩进、行距和段前间距，核对导出页面的 lvl、实际继承值及来源 part；不支持的图片仍使同一候选保持 partial。浏览器回归核对嵌套级别、实际 computed style、编辑后恢复基础值、捕获后的级别身份，以及混排文字的占位符绑定和 PPTX 写出。

同层冲突回归覆盖项目符号、字体、大小、颜色、制表位、行距、run 下划线及外来命名空间；真实 PPTX 在原本完整的布局中插入 buChar + buNone，验证生成结果变为 partial，且不会进入可注册的 native-layouts，其他有效布局仍保留。

字符项目符号回归覆盖源主题字体及带亮度变换的颜色 → 原生契约 → 实际导出回读，以及九级切换、符号／随正文样式、点值／百分比、空段、局部取消、单形状和正文不含符号。居中与非负缩进已有来源生成、浏览器捕获和原生回读；注册候选不等同于应用视觉验收。浏览器测试覆盖编辑、画布缩放、错误标记与缺少显式框体的阻断。字体收集沿实际页面／布局／母版关系解析可见标记，将符号字形加入对应字体子集输入；该采集不改写保存的正文或布局 XML，也不证明目标字体存在或允许嵌入。

多段文本框另有实际 ZIP 回读，检查唯一形状、逐段唯一 pPr、level、缩进、空段、前后和连续软换行、普通／强调 run、脚本字体及链接关系。真实浏览器覆盖多段捕获、编辑后更新、继承绑定和不支持内容的导出阻断。浏览器百分比行距按 CSS ratio/em 计算，没有采用参考渲染器的经验 Office 行高系数，也不据此声明 Office 视觉等价。

文本框回归验证实际源母版的内边距／底部对齐／禁用折行，在布局只声明左侧零值和 noAutofit 后，仍正确投影及回读其他继承属性与来源。浏览器在非等比画布上检查纵横内边距、底部对齐和捕获完整框体；PPTX 回读检查实际 bodyPr、单边覆盖及换行。当前锁定的 PptxGenJS 文本写入器使用 left/right/bottom/top 的 margin 数组顺序，适配按真实 ZIP 结果验证，未依赖其文档描述的 CSS 顺序。

参考只读快照 `references/pptx-renderer`（Apache-2.0，commit `2e8cd2222a889451bc872df50941f927cc79c7a2`）的 TextRenderer 分层合并和 kerning 语义，以及 `references/ppt-master`（MIT，commit `be8089296767d3e8cf012e07ea31c8716591bad8`）的列表样式物化边界。当前实现按 FastPPT 的 typed analysis / provenance 重新编写；参考实现和上述回归均不构成 PowerPoint/WPS/Keynote 的兼容验收。

自动编号保存 `scheme` 与模板默认 `startAt`；当前物化 16 种 Arabic／Latin 字母／Roman 样式。源节点及其来源仍保留，未知类型、非法起点和与可复用默认值不同的示例段落不会被静默归一化。页面主动重启使用独立 `numberingRestart`，浏览器和写入共用文本框内逐级计数规则；普通文本／空段不消耗编号，上层列表项重置下级。连续段导出省略本地 startAt，数字从不进入正文或单独生成形状。

新增真实源编号 → 分析 → 主题生成 → Layout → 原生导出／回读与浏览器编辑／缩放／分框／异常标记回归。独立 LibreOffice 检查覆盖 21 页，其中 19 页编号符合预期，2 页重启行为有已知差异，见[可复现证据](validation/numbering-compatibility.md)。编号字体子集采集对应格式的完整小字符集合，避免依赖单一应用的重启解释；这仍不等于完成 Office 字体度量或编辑验收。

制表位现在保存 `defaultTabSize` 与 `tabStops` 的独立来源及继承：列表整组替换，`[]` 清除，显式零默认间距保留。生成器拒绝非法位置、乱序／重复停止点、外来节点及未支持属性；小数点停止点继续使源候选 partial；居中和右停止点已有完整字段测量。原生写入按 schema 顺序将 tabLst 放在标记之后、defRPr 之前，页面布局继承只移除布局已声明的对应组。

左对齐 LTR 的源浏览器测量、显式文本框捕获、原生输出和实际回读已接通。Vue 编译原本会将正文 Tab 压成空格；新增只作用于显式文本框正文的编译前保留步骤，属性、代码和 Vue 表达式保留，FastPPT 宿主与生成主题的独立 Slidev 均有浏览器验证。缩放时处理浏览器亚像素舍入，连续 Tab 不会重复停在同一位置；字体加载后也重新测量。混排字形的高度可以超出 CSS 行高，捕获按同一显式行的字形纵向交集识别自动折行。自动折行及其他未测量组合仍阻断导出。

制表独立回渲染覆盖 15 页实际导出及 15 页诊断副本。实际产物 7 页吻合、8 页已知差异；移除 indent 的诊断副本 13 页吻合、2 页已知差异。后者不能替代真实导出验收。保留 indent/defaultTabSize/空 tabLst 的原始意图，并通过 text-tab-compatibility 提示应用复核；详情及版本／哈希见[制表兼容证据](validation/tabs-compatibility.md)。

居中／右停止点已按下一个 Tab 或显式软换行界定字段，跨 run 量取文字宽度，使用同一便携模块投影和复核。字段过长时将 Tab 间隔压到零，不采用参考渲染器的默认网格跳转；连续空字段消耗停止点，显式停止点之后恢复左对齐默认网格。真实导入回读保留 ctr/r，浏览器验证 CJK 混排、强调、空字段、br／文本内软换行、编辑、缩放、长字段及过期间隔的阻断。自动折行检查同时看纵向交集与 LTR 横向回退，避免极小行高掩盖视觉换行。

独立制表报告已扩展到 33 页实际导出与 33 页诊断副本：前者 7 页吻合、26 页已知差异；后者 27 页吻合、6 页已知差异。新增的 4 个德语／法语探针证明此 LibreOffice 版本不按 run 语言自动切换小数分隔符；DrawingML 本身也没有 Tab 分隔符字段。此项仍需明确应用环境约定，不能由浏览器 Intl 默认值替源文件补事实。


2026-10-09：主语言 `lang` 和备用语言 `altLang` 已贯通来源分析、模板生成、锁定 IR、浏览器捕获和原生输出，分别映射到 `language`／`alternativeLanguage`。字段缺省继续继承，显式 `""` 表示语言未知并阻断该字段的上层声明；保留大小写与私有标签，不自动规范化。当前校验是长度与传输语法校验，不是完整 BCP47 注册表验证，也不代表应用支持该语言。源文件的非法值保留原始证据和定位问题，使候选保持 partial。

Vue 将主语言投影为 `lang`、备用语言投影为 `data-fastppt-alt-lang`，逐级默认值独立覆盖。作者在段落、列表或内联节点声明的字段优先于模板默认值；空段、嵌套列表、编辑后级别切换和画布缩放均已验证。固定文字目前只保留统一的语言对；不同 run 的语言差异仍属于混合样式，不能静默压平。

PptxGenJS 4.0.1 会为缺省／空 lang 合成 en-US，并为声明 lang 的 run 额外合成 altLang=en-US。FastPPT 对 addText 的输入记录独立语言声明，在写入器完成拆段后恢复确切值，再写入原生文本框的段落默认值；保存文件与内存序列化走同一恢复路径。写入前复制嵌套选项，避免链接关系编号回写到调用者。原生布局的空占位符不再添加固定 en-US。该修复作用于正文和已定义的原生布局文字，不是对备注、图表或第三方种子所有语言字段的全局清洗。

回归覆盖真实母版默认值 → 源布局生成 → 原生输出 → 逐属性来源回读、主／备用语言独立继承与清除、混排分段、软换行、链接、空段、固定文字及非法来源阻断。参考 `pptx-renderer` 的 `TextRenderer.ts`／`fontResolver.ts` 将两种语言用作字体提示，但不把其提示逻辑当作小数分隔符约定。语言契约落地后，decimal 仍保持 partial，RTL、复杂 run 装饰及目标应用编辑矩阵也未随之完成。


小数点制表位现有独立的来源与环境证据模型：分析器遇到 decimal 停止点时记录 `decimalTabConvention.status=unknown`，原始属性与定位保持不变，模板选择文件传递该状态。`DecimalTabEvidenceV1` 分开保存源声明、目标应用的实际区域设置、配置摘要、两个产物阶段和逐页结果；不以外部 JSON 自报的 matched 作为支持授权。隔离 LibreOffice 的 en-US／de-DE／fr-FR 配置与 UNO／PDF 观测已确认系统区域设置的作用，见[可重放探针](validation/decimal-compatibility.md)。浏览器的 decimal 测量现已通过显式声明绑定，未知来源继续 partial。


`paragraph.decimalTab`（或独立级别的同名字段）保存 `separator`、`provenance: user-declared`、`reason` 和 `targetProfile`。缺省继承、null 清除，独立于 tabStops/defaultTabSize；缩放不修改声明。源生成可通过 `--decimal-tabs` 输入与源 PPTX 哈希绑定的全文件声明，保留原始 unknown。仅有源声明不足以推断应用兼容；当前测量配置绑定 LibreOffice 7.3.7.2 Linux 的 en-US／de-DE／fr-FR 诊断报告及已知生产差异。

2026-10-09：制表字段支持经测量的自动折行。浏览器使用 pre-wrap／普通断词／长词断行，Tab 移行后重新选择停止点，迭代稳定后再捕获；decimal 前缀使用跨行累计字形宽度。`paragraph.tabLayout` 保留原文、UTF-16 范围、作者软换行与自动行的区别、Tab 偏移和字形边界，原生输出不添加自动换行。过期正文、不连续范围、错误 Tab 偏移、伪造换行种类及未稳定布局均阻断。独立 66 页应用探针、实际 XML、浏览器和独立主题证据见[文字流验证](validation/text-flow-compatibility.md)。剩余标记几何与临界字宽差异仍保持明确边界。

## 单下划线、单删除线与显式取消

2026-10-09：`underline`／`strike` 已从来源 run 和默认样式贯通 NativeCharacterStyle、IR／MCP、锁定模板、源 Vue、捕获与原生回读。缺省继承，false 分别写为 `u=none`／`strike=noStrike`；各级只覆盖自己声明的字段。布局绑定移除声明的属性时，下划线同时移除局部 uLn/uFill 组，删除线不影响下划线子属性；普通 run、BR 和段尾均参与该规则，链接关系不受影响。统一样式固定文字也保留这两个字段。

模板装饰投影到文字叶节点，作者 `data-fastppt-underline`／`data-fastppt-strike` 的 true/false 可在子树独立覆盖。段落和 BR 只携带默认元数据，避免 CSS 祖先装饰使局部取消失效；普通 HTML u/s 仍按实际浏览器传播。生成的跨脚本叶节点只有样式一致时合并成原始文字对象。显式文本框的软换行写入独立装饰属性，取消不会因 writer 省略 false 而重新继承段落默认；空段与段尾保留各自默认值。

真实生成回归核对母版来源、逐级取消、固定文字与再次分析；双线、双删除线和自定义下划线填充使候选保持定位 partial。浏览器覆盖显式框体／普通文字、混排、嵌套取消、HTML u/s、链接、空段、软换行、Tab、项目符号、编辑、缩放和独立主题。篡改颜色、线型、偏移、skip-ink 或元数据会阻断；继承装饰颜色与正文不同也不能静默转换。

独立 LibreOffice 12 页实际文件验证全部吻合，见[文字装饰证据](validation/decorations-compatibility.md)。连续下划线经过空格和下伸字形，Tab 空隙无线；源预览明确使用 skip-ink:none。该报告不声称浏览器与 Office 线宽／纵向偏移像素一致；字距、基线、kerning／大小写、RTL 与复杂 body 仍按执行计划逐项实现，应用矩阵和实际产物规则门禁继续进行。


## 字距、零值取消与原生写入

2026-10-09：`letterSpacing` 已贯通来源 → NativeCharacterStyle／固定文字 → IR／MCP／锁定模板 → 源 Vue／捕获 → 布局绑定 → 原生回读。来源 `rPr@spc` 按百分之一点转为点值，原始字符串和逐属性来源保留；非法整数、越界值继续给出 part/shape/run 定位问题，使候选保持 partial。缺省继承、零清除、负值压缩，九级样式互不借值；契约和缩放结果均须在 -4000 至 4000pt 的有限范围内。

占位符与统一固定文字随横向画布比例缩放，源 Vue 使用 cqw；CSS 零值即使被 computed style 返回为 normal，捕获仍保存零。作者普通 CSS 行内覆盖保留到页面 run；普通跨脚本文字保持同一来源对象，显式框体的段落、空段、软换行、链接和 Tab 保持原结构。布局绑定只在该级声明字距时移除本地 spc，删除 run、BR、默认与段尾的声明时不影响其他格式。

PptxGenJS 会省略 charSpacing=0。FastPPT 扩展已有逐 run 属性恢复记录，在 writer 拆段后恢复明确声明的 spc，包含继承自 addText 选项的值和局部零值；没有声明的调用不被强加零值，调用者对象保持不变。显式框体的段落默认／段尾和 BR 字符样式分别写入，自动折行不写成原生软换行。

真实源回归验证母版字距来源、布局零值／负值覆盖、固定文字和再次分析；浏览器验证实际字距、混排、链接、空段、软换行、Tab、窄框、编辑、缩放、独立主题及超范围导出阻断。独立 [18 页应用证据](validation/letter-spacing-compatibility.md)为 15 吻合、3 个中英混排已知差异；实际 PDF 字符位置与原始产物摘要保留。非零字距导出附加 text-letter-spacing-compatibility，不以属性保存成功声明跨应用排版一致。下一项为基线偏移及其浏览器／原生位置语义，随后处理 kerning／大小写、RTL 和复杂 body。
