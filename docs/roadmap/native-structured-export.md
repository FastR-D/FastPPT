# 表格等结构化内容的原生 PPTX 导出计划

更新日期：2026-10-20。状态：N0 的表格契约与 N1a 首批已实现；结构回读和浏览器验证已通过，应用编辑验收未完成。原始代码核查基线：`9bd5cd65`。

目标是让用户在 PowerPoint 中继续修改表格、数据和结构。表格应成为真正的表格对象，数据图表应保留可编辑数据，流程图应保留节点和连接关系。原生形状、原生表格、原生数据图表、矢量图片和位图分别报告；仅有可编辑文字不足以证明结构保留。

本文细化 [PPTX / Theme / Motion 深化计划](pptx-theme-motion-evolution.md)中的结构化导出能力。下方“当前实现与缺口”保留实施前快照；本次交付进展见本节，不由后续规划推断已经支持。

## 首批实施进展（2026-10-20）

- 新增 V2 `table` 元素及完整矩形网格校验；V1 保持兼容。浏览器 ready、工作台和 Gateway 导出任务协商快照版本，消息协议仍为 V1。chart/OMML 契约尚未实现。
- 普通 HTML/Markdown 表格经过整表捕获、原生 writer、实际 PPTX 回读和协议报告，输出真正的 `a:tbl`。支持折叠的纯色实线边框、表头、非等宽列、空格/空单元格、中英文、inline rich runs、链接、显式换行、填充、内距和三种垂直对齐。表格接管子树，caption 单独保留；页面缩放和文字编辑后重新测量。
- 合并、分离的边框布局、复杂媒体/效果/嵌套表格、复杂文字等转为带语义损失记录的片段；严格模式即使零图片也会拒绝。非法矩形网格、捕获丢失和原生表格越界阻断导出，不自动拆页或缩字。
- 服务端为原生表格修正底层 writer 的对象 ID、边距单位、独立换行和 rich run 显式取消；输出后核对实际表格、行列、文字、几何、内距、基础样式和映射。报告区分结构 `passed` 与视觉/应用 `unverified`，表格文字纳入全局 QA，字体报告和嵌入扫描继续覆盖表格。
- 本批能力仍为 `partial`。N1b 合并单元格、N1c 完整组件/Skill 迁移、主题规则的表格内容度量、跨应用编辑和 N2–N4 继续待实施。验证与已知边界见[原生表格验证记录](../validation/native-table-export.md)。

## 1. 当前实现与缺口

| 链路 | 已有实现 | 本轮确认的缺口 |
| --- | --- | --- |
| 底层创作 API | `packages/slidewave/src/slide.ts` 提供 `addTable`、`addChart` | 不能据此推断 Slidev 工作台已接通；现有表格包装也不能直接当作完整合并单元格契约 |
| 浏览器捕获 | `slidev/capture.ts` 捕获 DOM 的形状、线条、文字和图片 | 没有表格整体捕获入口，表格会走普通 DOM 拆分路径 |
| 快照 | `snapshot-types.ts` / `snapshot.ts` 的 V1 联合类型只有 `shape/line/text/image` | 不保留行列、单元格、合并关系或图表系列语义 |
| 服务端 writer | `server/presentation.ts` 支持基础对象；`addDiagram` 消费共享布局 | `NodePresentationSlide` 未暴露原生 table/chart 操作；图中箭头由线形状绘制，尚无节点连接端点契约 |
| 导出策略与报告 | 已有 `editable/strict-editable/visual-fidelity`；按对象报告 native/image 数量 | 严格策略当前主要检查丢失对象与图片降级，无法识别“表格被拆成可编辑碎片”的语义损失；协议报告 kind 也只有四类 |
| 表格回归 | `test/slidev/table-render.test.ts` 验证蓝色底块和文字样式 | 夹具手工构造 shape/text，未验证浏览器表格捕获或实际文件中的表格结构 |

相关生产入口为 `apps/gateway/src/export-jobs.ts` → `packages/slidewave/src/server/index.ts` → `slidev/render.ts` → `server/presentation.ts`。沿用浏览器捕获、序列化快照、Gateway 排队和服务端写文件的职责；服务端不启动浏览器。

## 2. 表示选择与范围

| 源内容 | 目标原生表示 | 必须保留的编辑能力 | 实施阶段 |
| --- | --- | --- | --- |
| Markdown / HTML 表格 | `p:graphicFrame` 中的 `a:tbl` | 修改单元格、插入删除行列、调整列宽，合并表支持拆分与再合并 | N1 |
| 带源数据的柱状、折线、饼图 | chart part、关系及嵌入 workbook | “编辑数据”后系列和图形同步变化，标签与数值一致 | N2 |
| 流程图、组织图、时间线、矩阵、甘特图 | 原生形状、文本、分组及适用的连接器 | 编辑节点和标签；声明连接关系的图在移动节点后保持连线 | N3 |
| 普通列表与文本 | 原生文本及段落属性 | 原文、层级、编号和样式可修改 | 沿用已有链路，表格内复用受支持子集 |
| 公式 | 经验证的 OMML 子集 | 可在目标应用公式编辑器中修改 | N4，独立研究与验收 |
| 原始照片、截图、装饰图片 | 图片对象 | 调整图片、裁剪和位置 | 保持图片语义 |

原生形状组合可以用于图示，但不称为 SmartArt。没有源数据的图表图片不推断出数值；任意 SVG 不自动视为可编辑图表。CSS Grid/Flex 排版只有在显式声明表格或图示语义并通过校验后才进入对应转换器。

## 3. N0：结构契约、版本与降级规则

1. 由 `slidewave/snapshot` 定义运输契约的唯一 schema/type；拟新增 V2 的 `table/chart` 元素。业务 IR、编译器和工作台组件提供源模型适配，`protocol` 继续复用快照契约，不在 Gateway 复制类型，也不让 Slidewave 依赖应用包。
2. 继续接受并按既有逻辑处理 V1。V2 由浏览器运行时与 Gateway 协商支持版本后发送；旧服务端收到 V2 必须明确拒绝，不能丢弃未知元素。同步检查 browser protocol、打包后的 runtime、MCP/CLI 和报告消费者，快照版本与消息协议版本分别处理。
3. 给结构对象保留稳定 `elementId`、来源路径/anchor、页 ID、逻辑模型及测量几何。表格单元格、图表系列、图示节点拥有子 ID；导出后保存到实际 PPTX 对象/part 的映射，供回读、动画和错误定位使用。
4. 拟扩展报告字段：`semanticKind`、`representation`、`requiredRepresentation`、`semanticPreserved`、受影响子 ID、降级原因及结构/渲染/应用各自的验证状态。最终命名在 N0 定稿；保留原有计数用于兼容，不能用 `nativeCount > 0` 代替结构验收。
5. `strict-editable` 下，声明要求原生表格/数据图表/连接关系的对象若失去相应语义，即使全由 shape/text 组成也必须失败。旧 V1 无法可靠恢复结构要求，继续旧语义并明确未验证结构，不承诺自动补全。
6. `editable` 默认尝试原生；无法表达时可使用报告过的原生形状组合或局部图片回退，并标记语义损失。`visual-fidelity` 可使用报告过的局部图片回退。源内容丢失在所有策略下都失败，回退不绕过整页栅格与其他既有质量门禁。

N0 的首个交付是版本化 schema、策略矩阵和能力报告回归，包含“零图片但表格语义已丢失”的失败反例。它只依赖现有导出链路，不等待全部模板文字格式完成。

## 4. N1：优先打通真正的表格

### 数据与捕获

- 标准 HTML `<table>`（包括 Markdown 渲染结果）自动识别；自定义组件输出同一语义结构，或提供通过校验的显式表格模型。优先捕获表格再进入通用 DOM 遍历；成功接管后消费该子树，避免背景、边框与文字重复输出。caption 和脚注保留为独立文本并关联表格。
- `HtmlTableElement` 保存整体边界、列宽、行高、表头范围和单元格网格。单元格保存 row/column、rowSpan/colSpan、段落与 rich runs、四边框、填充、四边内距、水平/垂直对齐、字体与链接；逻辑文字与浏览器自动换行分开保存。
- 归一化 `thead/tbody/tfoot`、隐式行组、空单元格及 HTML 的有效 span。合并锚点与被覆盖槽位分开记录；拒绝重叠、越界及无法形成矩形网格的输入，不通过删格或补文本掩盖错误。设置行列、单元格数量、文本长度和几何范围预算，避免恶意快照拖垮服务端。
- 浏览器测量最终样式和网格边界，统一消除预览缩放并使用 CSS px。明确 `border-collapse` 冲突决议与 `border-spacing` 的支持范围。首次支持折叠边框、纯色填充、水平文字；嵌套表格、图片单元格、伪元素、复杂变换、渐变和裁剪逐对象诊断，不静默忽略。

### 原生写入与分期

| 切片 | 实施落点 | 完成条件 |
| --- | --- | --- |
| N1a 基础表格 | 新增表格捕获/归一化模块；扩展快照；`render.ts` 分发；`NodePresentationSlide.addTable` 和操作记录 | 普通矩形表格真实输出为一张 `a:tbl`，支持表头、空格、中文/英文、rich runs、边框/填充、内距/对齐、实测行列尺寸与字体报告 |
| N1b 合并与版式 | span 网格；PptxGenJS 适配；必要时增加受控 OOXML 补写及独立回读 | 横向、纵向及组合合并结构正确；长文本、多行、链接、显式换行、非等宽列保持内容完整；PowerPoint 中拆分/合并可用 |
| N1c 创作与交付 | 共享表格组件/源模型适配、协议报告、Gateway/Web/MCP/CLI、主题规则与 Skill 示例 | Markdown 与组件两条真实链路均通过；错误可定位到源表格/单元格；发布包与工作区行为一致 |

服务端适配复用底层写表能力，不能把 `slide.ts` 的主题默认值和宽松 `PrimitiveOptions` 直接充当捕获表格的契约。输出时将 px 转为目标英寸/pt，颜色与显式零值保留；核查底层库对行高、合并、字体、语言和段落的实际写出行为后再宣布支持。

默认一张源页对应一张输出页，关闭表格自动分页；超高表格明确报错或提供需要源稿修改的诊断。不能自动拆页、缩字、增高覆盖邻近内容或把自动折行硬编码为新的源换行。行高与字体的应用差异通过实际渲染检查发现，结构回读不能替代版式检查。

## 5. N2–N4：其他结构按语义扩展

- **N2 数据图表**：从已校验源模型获取类别、系列、数值、格式和轴信息；首批支持柱状/折线/饼图。接入服务端 `addChart`、操作记录、chart/workbook 关系回读及字体/内容报告。验证 workbook 与 chart cache 一致，修改数据并保存重开后仍一致。高级组合图、双轴、外部数据源单独分期，不从 SVG 路径或截图反推数据。
- **N3 图示**：沿用 diagram-engine 与 `diagram-layout` 的共享布局结果，补节点/边 ID、分组和连接端点契约。基础节点用形状与文本；需连接的边写入连接器及真实 shape ID 关系。先验收现有流程图，再扩到组织图、时间线、矩阵和甘特图；文字、节点、边及编辑后重连分别验收，普通带箭头线条不能证明连接关系已保留。
- **N4 公式**：先限定来源格式、支持语法及目标应用，验证 OMML 写入、回读、公式编辑、保存和重开。未通过的公式保持局部显式降级，SVG/图片不计为原生公式；该研究不阻塞 N1。

## 6. 验收门禁与样例

| 层级 | 表格首批必须验证的内容 |
| --- | --- |
| 契约 | V1 兼容、V2 协商与未知版本拒绝；非法 span、重叠网格、非有限几何和数量预算被阻断；三种策略结果明确 |
| 真实浏览器捕获 | Markdown 和 HTML 表格；表头/首列强调、空单元格、非等宽列、中英混排、长文本、rich runs、链接、横纵合并；缩放/字体加载/编辑后再捕获；无重复 DOM 子对象 |
| 原生文件回读 | 根据对象映射验证 `graphicFrame/a:tbl` 数量、行列/合并、单元格原文、rich runs、尺寸和样式；没有额外重叠文本或意外分页；图片或碎片替代表格时策略能检出 |
| 全局质量门禁 | 纯表格页的源文字期望、单元格文字/字体收集、字体嵌入、对象统计、主题规则回读与动画目标均能识别 table；图表阶段同样识别 chart/workbook，不能因顶层没有 text 元素而跳过内容检查 |
| 视觉回渲染 | 独立渲染实际输出，与浏览器对照边界、边框、行列对齐、换行、溢出及相邻对象覆盖；为夹具固定容差，失败保留可解释差异，不通过截图替换修复 |
| 应用操作 | PowerPoint 修改单元格、插删行列、调整列宽、合并/拆分、保存和重开；WPS/Keynote 分别实测并标注版本。未获得的应用证据保持 `unverified` |
| 分发链路 | 工作区与打包后的 CLI/MCP 均从真实源稿捕获、导出、回读；旧客户端/新服务端与新客户端/旧服务端按版本策略处理 |

保留现有 `table-render.test.ts` 作为碎片表示的视觉兼容回归，另增真实捕获及文件回读样例，不能只把手工夹具的 kind 改成 table 就声称端到端完成。复用 `tests/e2e` 的浏览器与应用探针基础设施，新增结构化导出黄金样例；表格对象清单与期望模型独立构造，避免 writer 自证。

每个保留运行记录源稿/模型、工具版本、字体与区域设置、源与输出摘要、捕获快照、PPTX、回读结果、浏览器截图、实际渲染图及能力报告。分别报告结构正确、视觉通过和应用编辑通过，不合并成一个未经验证的“支持”状态。

## 7. 执行顺序

结构化导出按 **N0 → N1a → N1b → N1c → N2 → N3 → N4** 推进，第一轮可评审交付为基础原生表格与“碎片不能通过结构要求”的策略反例。N1 的实际产物证据与现有 R1.3/R1.4 规则阶段、渲染门禁对接；各主题不必先完成全部模板格式迁移才能使用基础表格。

PPTX 导入中的表格/图表反向提取另立后续切片，不是 N1a 的前置条件，也不能由导出通过推断已经支持。主题组件、公共/托管 Skill 与示例只在对应能力贯通并验证后更新承诺。每个切片须同时交付契约、真实入口、原生产物、回读与能力报告；应用尚未验收时如实保留 partial/unverified。
